# 제품 가이드

현재 구현된 기능의 상세 동작과 HEIC 지원 범위를 설명합니다. 제품 개요와 실행 방법은 [README](../README.md), 판정 방식은 [판정 구조](architecture.md), 평가 방법은 [평가 가이드](evaluation-guide.md)를 참고하세요.

## 현재 기능

- **사진 가져오기**: 파일 선택기로 여러 장을 선택합니다. JPEG, PNG, WebP, HEIC(HEIF)를 받으며 확장자가 아닌 파일 앞부분의 시그니처(HEIC는 `ftyp` 브랜드)로 실제 형식을 확인합니다. HEIC는 브라우저가 직접 디코딩할 수 있을 때만 추가됩니다(아래 [HEIC 사진](#heic-사진)).
- **안전한 건너뛰기**: 지원하지 않는 형식, 이 브라우저에서 열 수 없는 HEIC, 손상되어 디코딩할 수 없는 파일, 이미 추가된 사진은 추가하지 않고 사유별로 안내합니다.
- **중복 기준**: 바이트가 완전히 같은 파일을 같은 사진으로 봅니다. 이름이 달라도 내용이 같으면 중복이고, 이름이 같아도 내용이 다르면 다른 사진입니다. 크기가 같은 파일끼리만 내용을 나눠 읽어 비교합니다.
- **갤러리**: 썸네일 그리드와 총 개수를 표시하고 사진 추가와 개별 목록 제거를 지원합니다. 목록 제거는 앱 안에서만 일어나며 기기의 원본 파일은 삭제하지 않습니다.
- **원본 보존**: 선택한 `File` 객체를 그대로 보관합니다. 썸네일은 원본과 분리된 화면 표시용 JPEG 미리보기이며 Object URL은 제거·화면 종료 시 해제합니다. 새로고침하면 목록은 유지되지 않습니다.
- **흐릿한 사진 감지**
  - 사진을 추가하면 기기 안의 Web Worker에서 선명도를 분석합니다.
  - 흐림이 의심되는 사진에는 추정 원인에 따라 `흔들림 의심`, `초점 불량 의심`, 원인을 구분하기 어려우면 `흐림 의심` 표시가 붙습니다. 판정할 수 없는 사진에는 `분석 불가` 표시가 붙습니다. 선명한 사진에는 표시를 붙이지 않습니다.
  - 사진 칸 아래에 짧은 판정 사유(예: `한 방향으로 번진 윤곽`, `분석 시간 초과`)를 직접 보여 줍니다. 마우스를 올리지 않아도 되므로 터치 화면에서도 보입니다. 화면 낭독기는 사진마다 전체 문장을 읽습니다.
  - 갤러리 상단에 진행 상황과 원인별 장수(예: `흔들림 의심 2장 · 초점 불량 의심 1장 · 분석 불가 1장`)를 보여 줍니다.
  - 사진 한 장의 분석이 20초 안에 끝나지 않으면 그 Worker만 종료하고 `분석 불가(분석 시간 초과)`로 표시합니다. 다른 사진의 분석은 계속됩니다.
  - 판정은 참고 정보입니다. 사진을 자동으로 지우거나 바꾸지 않습니다.
- **비슷한 사진 묶기**
  - 바이트까지 같은 파일은 지금처럼 가져오기에서 빠집니다(`이미 추가된 사진`). 그 밖에 화면상 같은 사진과 비슷한 사진을 묶음으로 보여 줍니다.
  - `거의 같은 사진`: 크기·압축·밝기·선명도만 다른 것으로 보이는 사진입니다. 묶음의 모든 사진 쌍이 이 기준을 만족할 때만 이렇게 부릅니다.
  - `비슷한 사진`: 연속 촬영처럼 구도가 비슷하고 조금 움직였거나 일부가 다른 사진입니다. 근거가 약한 쌍이 하나라도 있으면 더 보수적인 이 표현을 씁니다.
  - 갤러리 상단의 `모든 사진` / `비슷한 사진끼리 보기`로 보기를 바꿉니다. 모든 사진 보기는 기존 배열과 조작을 그대로 두고, 묶인 사진 위에 `묶음 N` 표시만 겹쳐 분석 중에도 사진 칸이 움직이지 않습니다.
  - 묶음 보기는 묶음마다 제목과 근거를 보여 주고, 좁은 화면에서도 두 장씩 크게 나란히 놓습니다. 사진 칸·흐림 표시·남기기·제거 버튼은 기존 갤러리와 같습니다.
  - 상단에 `비슷한 사진 묶음 2개(5장) · 비교하지 못한 사진 1장`처럼 결과를 보여 줍니다. 분석하지 못했거나 윤곽이 부족하거나 비슷한 후보가 너무 많은 사진은 묶지 않고 `비교하지 못한 사진`으로 셉니다.
  - 사진을 자동으로 지우거나 바꾸지 않습니다. 사진을 추가·제거하면 묶음을 다시 계산합니다.
- **크게 비교**
  - 묶음 보기의 `크게 비교`를 누르면 묶음 사진을 화면 전체로 비교합니다. 넓은 화면(768px 이상)은 두 장을 나란히, 좁은 화면은 한 장씩 크게 보여 줍니다.
  - `이전 사진`·`다음 사진`, 아래 사진 목록, 좌우 방향키로 넘기고, 터치 화면에서는 좌우로 밀어 넘깁니다.
  - 512px 미리보기 대신 원본 파일을 그대로 보여 줍니다. 원본은 지금 보이는 사진(1~2장)만 읽고, 넘기거나 닫으면 바로 해제합니다. 원본을 읽는 동안에는 미리보기가 먼저 보입니다. 원본을 복사하거나 다시 인코딩하지 않습니다. 브라우저가 원본을 표시하지 못하면 미리보기를 그대로 두고 `원본을 표시하지 못해 작은 미리보기를 보여 줍니다.`라고 알립니다.
  - 사진마다 흐림 판정과 남기기 상태를 보여 주고 그 자리에서 남기기를 바꿀 수 있습니다.
  - 비교 중 분석이 끝나 묶음이 바뀌어도 연 때의 사진을 계속 비교합니다. 닫기 버튼이나 Esc로 닫으면 `크게 비교` 버튼으로 초점이 돌아오고 갤러리 스크롤 위치는 그대로입니다.
- **남길 사진 표시**
  - 사진마다 `남기기` 버튼으로 남길 사진을 직접 표시하거나 풉니다. 흐림 판정이나 묶음과 관계없이 사용자가 정하며, 같은 묶음에서 여러 장, 묶음 밖 사진도 고를 수 있습니다.
  - 남긴 사진은 색뿐 아니라 체크 아이콘과 `남김` 표시로 구분합니다. 화면 낭독기는 버튼의 눌림 상태로 읽습니다.
  - 모든 사진·묶음·남길 사진 보기와 크게 비교에서 같은 선택을 공유하고, 상단에 `남길 사진 N장`을 보여 줍니다.
  - `남길 사진만 보기`로 고른 사진만 모아 봅니다. 남기지 않은 사진은 지우거나 숨기지 않으며 `모든 사진`에서 계속 볼 수 있습니다.
  - 남긴 사진을 목록에서 제거하면 남길 사진에서도 빠집니다. 선택은 브라우저 메모리에만 있어 새로고침하면 사라집니다. 남기기만 바꿔서는 흐림·비슷한 사진 분석을 다시 하지 않습니다.

## HEIC 사진

### 지원 방식

- HEIC는 브라우저 자체 디코더만 씁니다. 변환 라이브러리나 WASM 디코더는 넣지 않았습니다.
- 디코딩할 수 있는 브라우저에서는 JPEG와 같은 경로로 미리보기·흐림 분석·비슷한 사진 지문·크게 비교가 동작합니다.
- 원본 HEIC `File`을 그대로 보관합니다. 미리보기(512px JPEG)만 별도 Blob으로 만들며 원본을 JPEG로 바꿔 원본처럼 쓰지 않습니다.
- 디코딩하지 못하면 `이 브라우저에서 열 수 없는 HEIC 사진`으로 따로 안내하고 나머지 사진은 계속 가져옵니다. 브라우저 미지원과 파일 손상은 구분하지 않습니다.
- HEIC와 그 JPEG 변환본은 바이트가 다르므로 중복이 아닙니다. 같은 장면이면 비슷한 사진 묶음으로 함께 보이고, 무엇을 남길지는 사용자가 고릅니다.
- 파일 선택기의 `accept`에는 형식마다 MIME을 정확히 적습니다(`image/heic`, `image/heif` 포함, `image/*` 미사용).
  - Mac Safari(WebKit)는 `accept`에 MIME이 정확히 없는 이미지를 고르면 목록의 첫 인코딩 가능 형식으로 바꿔서 넘깁니다.
  - 그래서 HEIC가 없으면 원본 대신 변환된 JPEG를 받게 됩니다.

### 브라우저별 범위

- HEIC를 직접 디코딩한다고 알려진 브라우저는 Safari 17 이상(iOS·macOS)입니다(caniuse·WebKit 발표 기준). HEIC 지원을 추가할 때는 실기기로 확인하지 않았습니다. 이후 2026-11-19에 iPhone 17 Safari의 파일 앱에서 저장소의 작은 HEIC 시험 파일(160×120) 가져오기·미리보기를 확인했습니다. 실제 촬영한 고해상도 HEIC 원본의 분석·처리 시간·메모리는 확인하지 않았습니다.
- Chrome·Edge·Firefox(데스크톱·Android)는 HEIC를 디코딩하지 않으므로 안내만 보여 줍니다.
- 자동 테스트 대상(Playwright Chromium·Pixel 7·WebKit)도 HEIC를 디코딩하지 못합니다. E2E는 실제 HEIC 파일로 미지원 경로를 확인합니다.
  - 이 파일은 Windows HEIF 이미지 확장으로 `e2e/fixtures/sunrise.jpg`를 인코딩한 `e2e/fixtures/sunrise.heic`입니다.
  - 지원 경로는 단위 테스트(디코딩 성공을 흉내)로만 확인했습니다.

### iPhone 사진 보관함에서 앱으로 돌아오기까지의 대기

- **처음 보고된 문제**: iPhone Safari에서 사진 보관함의 체크 버튼을 누른 뒤 선택 화면이 유지되어 멈춘 것처럼 보였습니다. 당시 PNG 스크린샷은 정상이었습니다.
- **JPEG 실기기 검증 결과**(사용자 확인, iCloud 사진 저장 공간 최적화 사용 중)
  - 사진 보관함에서 JPEG 1장 선택: 약 2초 후 앱 복귀.
  - 사진 보관함에서 JPEG 24장 선택: 약 10~15초 후 앱 복귀.
  - 파일 앱에서 JPEG 1장 선택: 거의 즉시 복귀.
  - 사진 선택 화면에서는 준비 상태나 진행률이 표시되지 않았습니다.
  - 앱 복귀 후에는 1/24 형태의 기존 가져오기 진행 표시를 확인했습니다.
- **해석과 남은 불확실성**: 앱에 파일이 전달되기 전 사진 준비 단계에서 기다릴 수 있습니다. 이번에 확인한 사진은 JPEG이므로 지연을 HEIC 변환 때문이라고 단정하지 않습니다. iCloud에 저장된 사진은 더 오래 걸릴 수 있지만, 이번 대기의 구체적인 원인과 iCloud 다운로드 여부는 확인하지 않았습니다. 위 시간은 관찰값이며 보장 시간이 아닙니다.
- **앱에서 한 일**: 첫 화면의 사진 선택 버튼 앞에 사진 보관함 화면이 잠시 유지될 수 있다는 점과 자동으로 닫힐 때까지 기다려 달라는 안내를 두 문단으로 표시합니다. 기존 중복 안내는 교체하고, 앱 복귀 후 가져오기 진행률은 유지합니다.
- **남은 실기기 확인**: 파일 앱의 HEIC 원본 가져오기·미리보기·분석·크게 비교와 다른 기기·사진 수에서의 준비 시간은 별도 확인이 필요합니다.

### 남은 한계

- 큰 HEIC(예: 48MP)는 미리보기·분석·크게 비교에서 원본 전체를 디코딩합니다. JPEG와 같은 방식이며, 동시 분석 상한과 한 장씩 가져오기는 그대로입니다.
- Chrome·Firefox 등에서 HEIC를 열려면 로컬 WASM 디코더(libheif 계열)가 필요합니다. 라이선스(LGPL)·HEVC 특허·번들 크기(수 MB)·모바일 메모리 문제가 있어 사용자 판단이 필요한 후속 과제로 남깁니다.
- AVIF(같은 HEIF 계열 컨테이너)는 지원 범위가 아니며 `지원하지 않는 형식`으로 안내합니다.

## 계획한 기능(미구현)

1. **빠른 정리**: 눈 감김 감지(흔들림·초점 불량은 흐림 감지와 원인 추정으로, 비슷한 사진은 묶음으로 구현, 바이트가 같은 중복은 가져오기에서 제외). 비슷한 사진의 실제 사진 검증, 남길 사진 저장·내보내기와 묶음 단위 정리는 후속 작업입니다.
2. **베스트 컷 추천**: 표정, 선명도, 조명, 구도 등을 고려한 추천
3. **사용자 선택**: 추천 결과 수정, 즐겨찾기, 원본 사진 내보내기
4. **개인화**: 사용자 선택 이력을 반영한 취향 학습(후속 단계)
