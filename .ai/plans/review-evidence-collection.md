## 완료 조건과 방식

1. 원격 PR·기본 브랜치 정책·전체 파일/댓글/리뷰/인라인/검사를 수집하고 두 번의 수집 결과를 비교한다. SHA·fingerprint·정책 SHA·수집 digest·보고서 hash를 계산한다.
2. 기존 신뢰할 Codex GitHub 결과는 기존 파서로 수집한다. 로컬 세션 결과는 구조화된 파일로 받아 대상·완료 상태·지적 수·리뷰 역할을 검증한다. 출처를 인증하지 못한 로컬 결과는 그 한계를 표시한다.
3. Codex 자체 리뷰를 독립 검증으로 인정하지 않는다. 필요한 reviewer·완료·근거가 없거나 blocking/unknown 지적이 있으면 확인 준비 완료로 보지 않는다.
4. CLI 기본 모드는 읽기 전용이다. 명시적 dispatch만 기본 브랜치의 보고서 등록 workflow를 요청한다. workflow는 기본 GITHUB_TOKEN으로 보고서만 쓰고 관리자 인증·확인·승인·병합 API를 사용하지 않는다.
5. 중복 등록은 보고서 key와 실제 봇 작성자를 함께 확인한다. 실패·오래된 상태·위조·API 오류를 테스트한다. 테스트와 전체 verify, 자체 리뷰, 별도 독립 검증 후 별도 PR을 만든다.

## 이번 단계의 경계

현재 collectReviewBasis는 관리자 명의 보고서와 관리자 /review-gate를 요구한다. 이를 봇 자체 선언으로 대체하면 기존 보호의 완화다. 따라서 기존 게이트·병합 판정 코드와 보호 설정은 바꾸지 않고 실제 판정 결과를 자동 조회한다. 봇 보고서는 승인 근거로 자동 채택하지 않는다.

이번 단계는 계산·수집·보고서 등록의 수작업을 없애는 기반이다. /review-gate 입력 자체의 완전 제거는 아직 활성화하지 않는다. 이를 위해 필요한 별도 인증 주체, 실제 사용자 승인 경로와 게이트의 새 승인 증명 검증은 후속 고위험 단계로 분리한다. 관리자 인증을 공유하는 외부 프로그램까지 이 코드가 막는다고 주장하지 않는다.

## 대안·위험·롤백

- 관리자 토큰으로 기존 보고서·확인 댓글 자동 작성: 사용자 승인 대행 위험 때문에 제외.
- 즉시 native Environment 승인으로 전환: 환경 보호·인증 분리·기존 병합 도구 증명 방식까지 바꿔야 하므로 후속 단계.
- 선택한 방식: 권한이 좁은 별도 보고서 workflow와 읽기 전용 수집기. 새 workflow의 쓰기는 issues:write(보고서 댓글)뿐이며 기존 게이트 권한은 바꾸지 않는다.
- 로컬 결과는 실제 AI 실행을 암호학적으로 증명하지 않는다. 보고서·0건 수치만으로 기존 게이트를 통과시키지 않는 경계를 유지한다.
- 동시 변경은 비교 실패로 멈춘다. 게시 직후 PR 변경은 막을 수 없으므로 보고서에 불변 대상을 표시하고 승인으로 사용하지 않는다.
- workflow는 기본 브랜치에서만 실행하고 PR 코드·의존성·셸 입력·AI·비밀정보·캐시를 사용하지 않는다. PR #12 병합 전에는 운영 활성화하지 않는다.
- 롤백: 새 CLI·workflow 사용을 중지하고 이 PR을 revert한다. 기존 게이트와 수동 승인 경로는 계속 동작한다.

## 검증

정상 수집·완료 결과, 누락/스킵/한도/unknown 지적, 자체/독립 역할 혼동, HEAD/base/정책/본문/결과 변경, 불완전한 페이지·중복 ID·권한/API 실패, 위조 봇·다른 workflow·다른 ref·중복/불명확한 등록을 검사한다. 기존 게이트가 봇 보고서만으로 성공하지 않는 회귀도 확인한다. npm run verify와 원격 CI를 실행하며 실제 workflow 등록은 기본 브랜치 도입 전 테스트 대역으로 검증한다.
